# 项目开发规范

## 1. 目标

本规范适用于毕业设计指南针的全部后续 AI 和人工开发。所有变更必须优先满足可维护性、可验证性和最小实现原则。

## 2. 目录与模块化

- 按职责拆分主进程、preload、渲染进程、数据访问和通用类型；
- 单个文件原则上不超过 250 行，超过时按职责拆分；
- 一个模块只负责一类变化，禁止把 UI、IPC、文件复制和数据库访问混在同一个文件；
- 新增功能先寻找现有模块和工具，禁止重复实现。

## 3. 命名

- 文件夹、文件、npm 脚本、资源名称使用 `kebab-case`，多个单词以 `-` 分隔；
- TypeScript 标识符使用 `camelCase`，React 组件和类型使用 `PascalCase`；
- 常量使用 `UPPER_SNAKE_CASE` 仅在确有常量语义时使用；
- 名称必须表达业务含义，禁止 `data`、`thing`、`handleStuff` 等模糊命名。

## 4. 注释与语言

- 所有新增代码必须写中文注释；
- 注释解释“为什么”，不要重复描述语句本身；
- IPC、文件复制、数据库迁移、错误兜底等边界代码必须说明安全或业务原因；
- 用户可见文本使用简体中文，代码中的技术名称保留英文。

## 5. Electron 安全

- 必须保持 `contextIsolation: true` 和 `nodeIntegration: false`；
- 渲染进程不得直接导入 Node.js 或 Electron；
- preload 只暴露白名单函数，不得暴露完整 `ipcRenderer`；
- 主进程必须校验来自渲染进程的路径、名称和状态；
- 文件写入失败不得静默吞掉，也不得覆盖原文件后才发现错误。

## 6. 数据和状态

- 数据库是项目统计的唯一事实来源，不维护手工统计副本；
- 项目删除、归档等破坏性操作必须有明确确认；
- 时间统一使用 ISO 8601 字符串保存；
- 模板导入后复制到应用数据目录，项目只保存模板版本和生成路径。

## 7. React 规范

- 页面组件只处理展示和用户交互，文件系统、数据库调用放到服务模块；
- 可复用 UI 拆为小组件，避免单个页面组件无限增长；
- 所有按钮必须有明确文本或可访问名称；
- 表单必须有空值、重复名称和路径不可写等错误提示。

## 8. 测试与提交

- 新增非平凡逻辑先写一个会失败的最小测试，再实现并运行测试；
- 每次提交前至少运行 `npm run build`；
- 提交信息使用 `type: short description`，例如 `feat: add project dashboard`；
- 一个提交只解决一个主题，禁止提交无关格式化和构建产物。

## 9. 依赖与范围

- 优先使用现有依赖、Node.js 标准库和 Electron 原生能力；
- 新依赖必须说明它解决了哪段无法用现有能力合理解决的问题；
- MVP 不提前实现 Word、自定义文档模板、云同步、登录和多人协作。
