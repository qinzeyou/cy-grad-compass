# 项目开发与技能复用开发文档

## 1. 文档目的

本文说明“项目开发”页面的当前能力和技能复用扩展方案，作为开发、联调和验收依据。

目标用户可以：

- 从 0 到 1 创建一个空项目或模板项目；
- 在已有项目上修改代码、修复问题或添加功能；
- 通过对话逐步完善项目，并暂停、继续当前开发；
- 把已有项目中的通用功能提取为技能，在其他项目中复用。

## 2. 名称约定

| 中文名称 | 技术含义 |
| --- | --- |
| 工作区 | 一个已登记的项目目录，使用现有 `projectId` 标识 |
| 开发会话 | 工作区下的一段持久化对话，使用现有 `sessionId` 标识 |
| 需求讨论 | Codex 使用 `read-only` 沙箱，只读分析和回答 |
| 项目开发 | Codex 使用 `workspace-write` 沙箱，可在当前项目目录内写入 |
| 技能 | 可复用的功能说明、约定和执行步骤，保存在应用技能目录 |
| 确认开发 | 用户确认当前需求可以写入项目的操作 |

代码文件和 TypeScript 标识符继续遵循项目规范：文件使用 `kebab-case`，变量使用 `camelCase`，组件和类型使用 `PascalCase`。页面标题、按钮、提示和错误信息使用简体中文。

## 3. 当前已实现能力

### 3.1 项目和会话

- 工作区实际复用项目目录，不新增工作区数据库表；
- 左侧按“工作区 → 开发会话”两级展示；
- 工作区和会话支持选中、切换、创建和悬浮删除；
- 会话和消息保存在 SQLite，应用重启后可以恢复；
- 会话标题由第一条用户消息生成，后续只显示标题。

### 3.2 Codex 开发

- 首条消息和讨论阶段使用本机 Codex CLI 的 `read-only`；
- 点击“确认开发”后，恢复同一 Codex thread 并切换到 `workspace-write`；
- 工作区范围由 Codex 的 `-C <project-path>` 限定；
- 支持停止、暂停和继续，继续操作恢复原 thread；
- 右侧显示运行状态、命令、文件变化、错误和日志；
- 不使用危险的全权限参数，不自动提交或推送 Git。

### 3.3 页面布局

```text
顶部：新增工作区（选择项目）  新建会话
左侧：工作区
      └─ 会话标题
中间：会话标题、用户/AI 消息、开发模式、确认开发、输入框
右侧：运行状态、暂停/继续、命令和文件变化
```

界面保持 ChatGPT 风格：低对比背景、少边框、会话只展示标题，当前选中态使用浅色背景，不使用大面积高亮。

## 4. 开发模式

输入框底部增加下拉组件，只提供两种模式，模式只对当前发送消息生效：

| 模式 | 权限 | 行为 |
| --- | --- | --- |
| 需求讨论 | `read-only` | 阅读项目、分析需求、给出方案，不修改文件 |
| 项目开发 | `workspace-write` | 修改当前工作区文件、运行必要检查并汇报结果 |

选择“项目开发”不会立即写文件，仍必须点击“确认开发”。确认后会话进入开发阶段，后续补充消息默认使用可写权限。

### 4.1 从 0 到 1

当项目目录为空或仅包含模板文件时，开发提示必须要求 AI：

1. 检查目录和现有约定；
2. 创建必要的目录、配置和基础代码；
3. 按需求逐步实现功能；
4. 运行项目已有的构建或测试命令；
5. 汇报已完成内容、未完成内容和运行结果。

### 4.2 已有项目增量开发

当目录已有代码时，开发提示必须要求 AI 先理解现有实现，再以增量方式修改或添加功能。不得覆盖无关文件，不得删除用户已有改动；完成后必须说明修改文件和验证结果。

## 5. 技能库

### 5.1 存储位置

技能为全局能力，保存在 Electron 的用户数据目录：

```text
<userData>/skills/<技能编号>/
  skill.json
  SKILL.md
  references/（可选）
  scripts/（可选）
  assets/（可选）
```

技能目录只由主进程管理。渲染进程不能直接读写文件系统。

`skill.json` 最小字段：

```json
{
  "id": "功能编号",
  "name": "功能名称",
  "description": "功能用途",
  "source": "imported | extracted",
  "createdAt": "ISO 8601 时间",
  "updatedAt": "ISO 8601 时间"
}
```

### 5.2 技能来源

支持两种来源：

- **外部导入**：用户选择一个符合技能目录结构的文件夹，主进程校验 `skill.json`、名称和路径后复制到 `<userData>/skills`；
- **项目提取**：从当前工作区和当前会话上下文提取通用功能。Codex 使用 `read-only` 阅读代码并生成 `SKILL.md`，用户确认后才保存技能。

提取必须去除项目专属路径、密钥、客户信息和不可复用的业务数据，只保留功能目标、适用条件、关键步骤、验证方法和必要参考文件。

### 5.3 技能管理

技能管理入口提供：

- 查看技能名称、说明、来源和更新时间；
- 导入外部技能目录；
- 从当前工作区提取技能；
- 删除技能，删除前二次确认；
- 查看 `SKILL.md` 内容。

技能选择器位于会话信息右侧，只显示当前选中工作区可安装的全局技能。未选中工作区时不显示技能选择器。

## 6. 技能安装流程

技能安装由 AI/Codex 执行，不直接复制固定代码：

1. 用户选中一个工作区；
2. 在会话信息右侧选择技能；
3. 若工作区没有会话，自动创建一个“技能安装”会话；
4. 页面把技能说明作为受控上下文加入开发提示；
5. 用户选择“项目开发”并点击“确认开发”；
6. Codex 检查项目现状，按技能说明实现功能；
7. Codex 运行必要检查并汇报修改文件；
8. 页面保留普通对话和运行日志，便于继续完善。

技能安装目标只能是当前选中的工作区，不能在一次操作中跨项目写入。

## 7. 主进程架构

现有开发模块继续使用：

```text
electron/development/
  codex-controller.ts
  codex-event-parser.ts
  development-repository.ts
  development-service.ts
  development-handlers.ts
  development-types.ts
```

新增技能模块：

```text
electron/skills/
  skill-service.ts
  skill-handlers.ts
  skill-types.ts
```

职责边界：

- `skill-service.ts`：目录扫描、导入、提取结果校验、读取和删除；
- `development-service.ts`：会话、消息、权限阶段和 Codex 调用；
- `codex-controller.ts`：只负责启动、暂停、继续、停止和解析 Codex 进程；
- IPC handler：只做参数接收和 service 调用；
- preload：只暴露白名单方法，不暴露 `ipcRenderer`。

技能服务不新增 SQLite 表。技能元数据和文件都以用户数据目录中的文件为事实来源；项目、会话和消息仍以现有 SQLite 表为事实来源。

## 8. IPC 接口约定

技能接口建议如下：

```ts
skill:list(): Promise<SkillSummary[]>;
skill:get(id: string): Promise<SkillDetail>;
skill:import(): Promise<SkillSummary>;
skill:extract(input: { sessionId: string; name: string; description?: string }): Promise<SkillSummary>;
skill:delete(id: string): Promise<void>;
```

开发接口扩展当前消息模式：

```ts
development:send-message(input: {
  sessionId: string;
  message: string;
  mode: 'discussion' | 'development';
  skillId?: string;
}): Promise<void>;
```

旧的会话创建、暂停、继续、停止和事件订阅接口保持兼容。所有输入在主进程校验：字符串长度、技能编号、会话归属、项目目录存在性和当前运行状态。

## 9. 安全和错误处理

- 技能导入路径必须是目录，且不能是应用内部技能目录本身；
- 技能编号只能来自主进程生成或校验后的 `skill.json`；
- 禁止技能安装过程把文件写到当前项目目录之外；
- 禁止将密钥、绝对用户路径和客户隐私写入技能；
- 技能文件损坏时显示“技能格式无效”，不影响已有技能；
- Codex 启动失败、认证失败、目录不存在和任务冲突沿用现有中文错误提示；
- 删除技能不删除已安装到项目中的代码，只删除技能库副本；
- 应用退出前终止活动 Codex 进程，避免后台继续写项目。

## 10. 验收标准

### 工作区和会话

- 左栏按工作区分组，工作区下只展示所属会话；
- 新增工作区后自动选中，已有会话打开最近一条，无会话显示轻量空状态；
- 顶部“新建会话”使用当前工作区的 `projectId`；
- 无选中工作区时“新建会话”禁用；
- 工作区和会话的悬浮按钮可用，删除行为不改变。

### 开发模式和运行控制

- 需求讨论不会修改项目文件；
- 选择项目开发后，只有点击“确认开发”才允许写文件；
- 空项目可以从 0 到 1 创建；已有项目可以增量修改；
- 暂停后任务不再产生新的写入事件，继续后恢复同一 thread；
- 非当前会话事件不会污染当前对话或运行面板。

### 技能复用

- 可以导入、查看、提取和删除技能；
- 技能选择器只作用于当前工作区；
- 无会话工作区选择技能会自动创建安装会话；
- 技能安装通过 Codex 完成，并显示消息、命令和文件变化；
- 应用重启后技能仍可从 `<userData>/skills` 读取。

## 11. 测试清单

使用项目已有的 Node.js `node:test` 和 Vitest，不新增测试框架。至少覆盖：

1. 技能目录导入、读取、损坏校验和删除；
2. 技能提取只读取当前项目，不越界访问其他目录；
3. 讨论、开发和技能安装使用正确沙箱；
4. 项目开发必须经过确认，未确认时不能写文件；
5. 暂停和继续恢复同一 thread，停止后不再接收新事件；
6. 技能选择器传递正确的 `skillId` 和当前 `projectId`；
7. 无会话工作区可以自动创建安装会话；
8. 现有项目管理、统计、订单和设置测试继续通过；
9. `npm run build` 和 `npm test` 通过。

## 12. 暂不实现

- 技能市场、远程同步和多人协作；
- 自动把技能安装到多个项目；
- 自动 Git commit、push 或创建 PR；
- 多 Agent 并发调度；
- 技能版本依赖解析和自动升级；
- 将运行日志跨应用重启持久化。
